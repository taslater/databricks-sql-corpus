# Keywords Databricks SQL needs that OSS Spark's lexer does not define.
#
# ONE entry here produces THREE things in the patched grammar:
#   1. a lexer token          OPTIMIZE: 'OPTIMIZE';
#   2. an ansiNonReserved entry
#   3. a nonReserved entry
#
# (2) and (3) are the important part. Defining a lexer token makes that word
# stop matching IDENTIFIER, so `SELECT optimize FROM t` or a column named
# `tag` would become a syntax error -- a recall regression that would block
# perfectly good merge requests. Listing every new keyword as non-reserved
# keeps it usable as an identifier, which is also what Databricks does.
#
# Deriving all three from one list makes it impossible to add a token and
# forget the other two.
